What Changed

A session planning four changes (sequence integration, wait_for_lock property, BigSky voltage skip, GUIs folder move) was interrupted when a diagnostic mv command partially moved BigSkyControl's directory. A subsequent rm -rf on the partial move destination destroyed local-only git commits. Recovery used Windows File History (Feb 24 backup) plus session context to restore documentation files. Safety rules were added to prevent recurrence. All four GUI repos were pushed to remote as an immediate safeguard.

Key Decisions

Two-layer defense: Safety rules are enforced at both the documentation level (CLAUDE.md instructions) and the tooling level (settings.json PreToolUse hook). The hook catches the command before execution; the CLAUDE.md rule prevents the command from being formed in the first place.
  • Push-after-commit policy: All four GUI repos pushed immediately. Going forward, unpushed-only commits are a known risk — push promptly after committing.
  • Read-only diagnostics rule: When investigating directory locks or filesystem state, use ls, stat, dir, Get-ChildItem — never mv or cp as a test.
  • Documentation rebuilt from context, not guessed: The CLAUDE.md and agent prompt were rewritten using the conversation's full session context, not from memory. This preserved the _sendCommand convention, disconnect lifecycle, and ZMQ error handling details accurately.

Safety Rules Added

CLAUDE.md "File Move/Delete Safety" Section

Destructive file operations (rm -rf, rm -r, mv on directories) require:
1. Explicit user confirmation before execution
2. Read-only commands (ls, stat) for diagnostics — never mv/cp as tests
3. Verify target is recoverable before deleting source

settings.json PreToolUse Hook

Blocks Bash commands matching:
  - rm -rf or rm -r (directory removal)
  - mv applied to directories
Triggers approval prompt — user must confirm before execution.
