BigSky Serial Disconnection Resilience

Date: 2026-02-24  •  Commit: pending  •  Context: Implemented automatic detection, recovery, and cross-system error propagation for USB-serial disconnects on the BigSky YAG laser controller hub.

What Changed

The BigSky laser controller GUI previously crashed or hung when a USB-serial cable was unplugged mid-session. This session added a centralized _sendCommand() wrapper that catches serial exceptions, a disconnect handler that resets all GUI state, a 5-second auto-reconnect timer, and hub-level tab graying. The ZMQ server now returns explicit ERROR responses for offline lasers, and the BLACS worker gracefully skips disconnected lasers instead of raising exceptions.

Key Decisions

Centralized _sendCommand() vs per-method try/except

All serial I/O now routes through a single _sendCommand() method that returns the response string on success or None on failure (triggering _handleDisconnect()). This ensures no serial call can bypass error handling. Raw self.ser.* calls only appear in three places: _sendCommand() itself, _attemptReconnect() (needs to test the port directly), and safeExit() cleanup.

Temperature query for reconnection validation

Reconnection uses >cg (temperature query) to validate the serial link, not >sn (serial number). The COM port already identifies the physical connection (USB-serial adapters have stable COM assignments on Windows), so re-verifying SN is redundant overhead. Temperature response also provides useful data to display immediately on reconnect.

ZMQ returns ERROR, not stale values

The ZMQ server returns explicit {"status": "ERROR", "message": "laser disconnected"} for offline lasers rather than cached values. PUB-SUB skips disconnected lasers entirely. This lets BLACS distinguish "laser offline" from "stale data", enabling proper error handling.

transition_to_buffered intentionally unchanged

A disconnected laser during a shot sequence should abort the shot, not silently skip. The existing transition_to_buffered error handling already raises on failure, which is the correct behavior for shot execution.

Bugs Found & Fixed

safeExit() tab-index shifting bug

Symptom: When closing the hub with multiple laser tabs, tabs beyond the first may not be closed properly.
Root cause: safeExit() used for i in range(1, self.tabs.count()) and called self.closeTab(i). After removing tab 1, tab 2 shifts down to index 1, but the loop tries index 2 next.
Fix: Changed to while self.tabs.count() > 1: self.closeTab(1), always removing index 1 until only the home tab remains.

How to Use

  1. Unplug a laser's USB-serial cable while the GUI is running.
  2. Within the next serial command or poll, the GUI detects disconnection:
    • Per-laser widget shows "DISCONNECTED" label in dark red, all indicators reset.
    • Hub tab shows "(OFFLINE)" in red text.
    • Terminal log records timestamp of disconnection.
  3. Reconnect timer starts automatically (5-second interval). No user action required.
  4. Plug the cable back in. Within 5 seconds, the GUI detects reconnection:
    • Re-opens serial port and validates with temperature query.
    • Re-queries voltage, frequency, lamp mode, Q-switch mode, energy.
    • Restores normal GUI state and tab appearance.
  5. During disconnection, BLACS receives ERROR responses and logs warnings -- no crash, no stale data.

Patterns Observed

Centralized serial gateway pattern. The _sendCommand() wrapper establishes a convention: all serial I/O goes through one method. Future serial commands should use _sendCommand() rather than direct self.ser.* calls.
ZMQ error propagation chain. Three layers handle the disconnect: (1) GUI detects serial loss and sets serialConnected = False, (2) ZMQ server checks getSerialConnected() and returns ERROR, (3) BLACS worker checks error message and logs warning. Future error conditions could follow the same chain.

Additional Changes (same session)

Rescan COM Ports button (HugeSkyController.pyw)

COM port discovery previously ran only once at hub startup. If a laser was powered on after the hub launched, it was invisible. Added a "Rescan COM Ports" button to the Home tab that re-scans all COM ports, skips already-known devices, and dynamically adds new laser entries with wired-up launch buttons.

BLACS per-laser disconnect indicator (BigSkyHub/blacs_tabs.py)

The BLACS tab now tracks per-laser PUB-SUB activity. Each laser group box starts grayed out with "(OFFLINE)" title. When the first PUB-SUB monitor value arrives (~250ms after connection), the group box is immediately re-enabled. A 10-second health timer detects lasers that go offline later (30s stale threshold) and grays them back out. This provides clear visual feedback in BLACS for which lasers are physically connected.

Agent definition update (bigsky-yag-laser-controller.md)

Updated the local bigsky-yag-laser-controller agent to document the _sendCommand() convention (replacing the old compact serial pattern) and the full disconnect/reconnect lifecycle including _handleDisconnect(), _attemptReconnect(), _handleReconnect(), connectionStatusChanged signal, ZMQ error responses, and rescanPorts().
