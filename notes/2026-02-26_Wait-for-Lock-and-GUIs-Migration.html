What Changed

Three independent improvements in one session. (1) The wait_for_lock flag, previously hardcoded to True in transition_to_buffered, is now a connection table property. Only the laser lock device needs it; BigSky and Rastering were blocking unnecessarily. (2) The Closed_cell.py sequence now programs all RemoteControl setpoints via .constant() calls, using RunManager globals. (3) The GUIs/ folder was moved from Desktop\GUIs into the labscript-suite workspace for co-location and simpler path management. All references across ~20 files were updated.

Key Decisions

Default wait_for_lock=False: The safe default is to NOT wait. Only devices that actively implement lock semantics (laser lock GUI) should opt in via wait_for_lock=True in the connection table. This avoids silent hangs on devices that don't respond to CHECK_VALUE with lock status.
getattr with fallback: Using getattr(self, 'wait_for_lock', False) instead of direct attribute access ensures backward compatibility. Old h5 files compiled before this change won't have the property set, so the worker falls back to False (no waiting) rather than crashing with AttributeError.
GUIs as subdirectory, not submodule: The GUIs folder is simply moved into the workspace and git-ignored. No submodule machinery needed because each GUI has its own independent git repo and release cycle. The co-location is purely for developer convenience (one terminal window, relative paths).

How to Use

wait_for_lock

  1. In the connection table, add wait_for_lock=True to any RemoteControl-derived device that supports lock confirmation:
LaserLockDevice(name='LaserLockGUI', host="127.0.0.1",
    reqrep_port=3796, pubsub_port=3797,
    mock=False, wait_for_lock=True)

Devices without this flag (or with wait_for_lock=False) will program values without polling CHECK_VALUE.

Sequence .constant() pattern

# In Closed_cell.py (after start()):
TiSa_1_Setpoint.constant(TISA_1)    # RunManager global
Raster_X.constant(RASTER_X)         # RunManager global
YAG_1_voltage.constant(V_YAG1)      # RunManager global

Values come from BaF_globals.h5. Change them in RunManager's globals editor.

Bugs Found & Fixed

Hardcoded wait_for_lock=True caused unnecessary blocking: BigSky and Rastering devices were calling program_value(..., wait_for_lock=True) in every buffered transition, causing the worker to poll CHECK_VALUE on devices that had no lock semantics. This added latency to every shot and could potentially hang if the GUI didn't respond to CHECK_VALUE correctly.
