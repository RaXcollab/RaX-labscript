Context Hardening: Post-Shutter-Incident Fixes

Date: 2026-02-27  •  Commit: pending  •  Context: Close 5 context gaps identified from a parallel session's shutter scoping incident; codify writing-style practices

What Changed

A parallel session proposed NI_DAQmx code that wrote ALL digital lines on a port instead of just the requested shutter line. Post-mortem identified five gaps in the agent context structure. This session created a labscript API reference doc, added hardware scoping rules, timing verification rules, a blacs-expert scope audit checklist, and codified context-file writing practices as a path-scoped rule.

Root cause of the shutter incident: The agent had no labscript API reference and guessed the Shutter constructor signature (separate kwargs instead of a delay tuple). It also proposed writing all DO lines on the port instead of scoping to the single requested line. Both gaps are now covered by docs/labscript-api.md and the hardware scoping rules.

Key Decisions

API reference as @import, not inline CLAUDE.md. The labscript API doc is ~100 lines. Keeping it in a separate docs/labscript-api.md file with an @docs/labscript-api.md import keeps CLAUDE.md scannable while still auto-loading the reference into every session.
Writing-style as a path-scoped rule. Rather than adding style guidance to every agent prompt, a single .claude/rules/context-writing.md auto-activates when editing any context file. This ensures consistent style without duplicating rules.
Bullet conversion in agent prompts. Narrative paragraphs in blacs-expert and amo-expert were converted to bullets per the new writing-style rule. Same content, better scannability.

Patterns Observed

  • Five-gap post-mortem pattern: A single incident (shutter scoping) revealed gaps across five different context layers (API reference, device rules, sequence rules, agent audit, writing style). Systematic post-mortems catch more than point fixes.
  • API guessing is the root cause: When the agent lacks an authoritative API reference, it fills gaps from training data. Training data signatures can be wrong (different labscript version, different device). The fix is always to provide the reference, not to add more warnings.
  • Scoping failures compound: The shutter incident had two independent failures — wrong API signature AND over-scoped DO write. Either alone would have been caught in testing; together they produced a harder-to-diagnose result.
