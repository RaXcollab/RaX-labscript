What Changed

This session implemented the fixes identified during the earlier audit (see 2026-02-23_Pre-scan_audit.html). The NI_SCOPE worker now writes time-axis metadata (sample_rate, t0, channels_saved) as h5 dataset attributes, and supports selective channel saving via channels_to_save. The analysis utilities gained backward-compatible deprecation aliases in filtering.py, exception logging in Abs_data.py, and auto-detection of sample rate in NI_SCOPE.py.

Key Decisions

NaN-padding for unsaved channels: When channels_to_save excludes a channel, its row in the 2D dataset is filled with NaN rather than being omitted entirely. This preserves the [channel_count, N] shape that all existing analysis code expects (channel 0 = row 0, channel 1 = row 1). The channels_saved attr records which rows contain real data.
Sample rate fallback chain: _resolve_fs_hz() checks 4 sources in order: (1) dataset attrs sample_rate (new files), (2) connection table property min_sample_rate, (3) user-provided fs_hz kwarg, (4) 1 MHz default. This means old h5 files (without attrs) still work, and new files auto-detect correctly.
Deprecated kwargs in filtering.py: Rather than breaking old notebooks, the old absolute-time parameters (beforeYAG_time, after_abs_time, end_time) are accepted, converted to the current relative API (margin_ms, tail_ms), and emit DeprecationWarning. This follows the API stability rule in CLAUDE.md.

Bugs Found & Fixed

NI_SCOPE h5 datasets had no time metadata. The sample_rate was never written to the h5 file. Analysis code had to hardcode 1 MHz or guess. Now written as dataset attrs on every shot.
Abs_data.py silently swallowed all exceptions. except Exception: pass in read_shot() meant corrupted or missing files produced no output and no warning. Replaced with a warning print showing filename and error.
Abs_data.py silently dropped shape-mismatched shots. When a shot's trace had a different length (e.g., from a config change mid-sequence), it was filtered out with no indication. Now prints how many shots were dropped per trace.

Patterns Observed

  • Generic audit agents produce false positives on domain-specific code. The initial audit (previous session) launched 3 parallel Explore agents that flagged 7 non-issues: RunManager globals as "undefined variables," register_classes.py as "missing," thread safety patterns as "incorrect." All were dismissed after manual review. Domain-routed agents (amo-expert, blacs-expert, lyse-analysis) would have avoided these.
  • NaN-padding is an effective backward-compat pattern for optional data columns. Preserves array shape and indexing semantics. Analysis code that doesn't check for NaN will produce NaN outputs (visible, not silent). Code that does check gets clean data. Worth documenting as a general convention.
  • Metadata-in-attrs vs. metadata-in-separate-dataset: h5 dataset attrs are the right place for per-acquisition metadata (sample_rate, t0). The connection table properties are the right place for device-level config. The fallback chain bridges both.

How to Use

Selective channel saving

In the connection table, specify which NI-5922 channels to save:

NI_SCOPE(
    ...
    channels_to_save=[0],      # save only channel 0
    channels_to_save=[0, 1],   # save both (default if omitted)
)

Unsaved channels appear as NaN rows in the h5 dataset. The channels_saved attr records which rows are valid.

Auto-detected sample rate in analysis

# New files (with attrs): auto-detects sample rate
data = load_ni_scope_sequences(folder, [1, 2, 3])

# Old files (no attrs): falls back to connection table or 1 MHz
# Can still override explicitly:
data = load_ni_scope_sequences(folder, [1, 2, 3], fs_hz=2_000_000)

Deprecated filtering.py kwargs

# Old API (still works, emits DeprecationWarning):
corrected = process_trace(t, sig, tYAG,
    beforeYAG_time=tYAG - 0.05,
    after_abs_time=4.0, end_time=5.0)

# New API (preferred):
corrected = process_trace(t, sig, tYAG,
    margin_ms=0.05, tail_ms=1.0)
