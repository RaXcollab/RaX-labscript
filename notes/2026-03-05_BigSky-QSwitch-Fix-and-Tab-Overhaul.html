What Changed

Fixed a critical Q-switch mode bug across both BLACS workers and the BigSky GUI: the arm sequence was setting Q-switch mode to external (qsm2) when our lab configuration requires internal (qsm0). External QS mode requires a separate delay generator we don't use. Simultaneously overhauled the BLACS tab UI from a single "Keep Warm" toggle to three explicit action buttons (Stop/Warmup/Arm Ext) with state-driven color feedback, plus an "Auto Re-Arm Ext" checkbox for the shot queue lifecycle. Also hardened the BigSky GUI with serial error handling, a COM port refresh button, and a tab-close index-shifting fix.

Bugs Found & Fixed

Critical: Q-switch mode was set to external (qsm2) instead of internal (qsm0). Both blacs_workers.py and BigSkyControllerAmbitious.py were sending >qsm2 during the arm sequence. Mode 2 (external) expects a separate trigger line for the Q-switch, which we don't have. Internal mode (0) uses the BigSky controller's built-in 140 us delay from flashlamp to Q-switch. This bug would have prevented proper lasing when the arm-external path was actually used.
safeExit() skipped tabs due to forward iteration with index shifting. HugeSkyController.pyw iterated for i in range(1, count) and called closeTab(i), but closing tab 1 shifts tab 2 into position 1, so the loop skips it. Fixed by iterating in reverse.
ZMQ PUB and CHECK_VALUE crashed when controller destroyed during tab close. The server's publish loop and CHECK_VALUE handler accessed controller state without guarding against mid-destruction. Added try/except with "laser disconnected" error responses.
updateTemp() crashed on serial disconnect. No error handling around serial read in the temperature polling loop. USB disconnect threw SerialException and crashed the timer callback. Added catch for serial and parse errors.

Key Decisions

Internal Q-switch is our standard mode. Our lab uses lamp_mode=1 (external) + qswitch_mode=0 (internal). The BigSky controller handles the 140 us Q-switch delay internally after each flashlamp trigger. External QS mode (2) would require a delay generator, which we don't use. This was documented in the new yag-laser-physics.md reference to prevent future agents from repeating this mistake.
Decoupled manual control from auto-lifecycle. The old "Keep Warm" toggle both sent hardware commands AND set the auto-rearm flag. The new design separates these: Stop/Warmup/Arm Ext buttons send hardware commands directly via send_action(), while the "Auto Re-Arm Ext" checkbox only sets the flag for transition_to_buffered/transition_to_manual lifecycle hooks.
Fire-and-forget channels skip program_manual. Commands like warmup, start_lasing, and stop are action-type channels (defined in _COMMAND_SUFFIXES) that BLACS's program_manual path intentionally skips. To send them from tab buttons, we use queue_work(worker, 'send_action', ...) to dispatch directly to the worker.
Hardware verification before skip-rearm. The _auto_arm_if_needed() method now uses _verify_armed_state() to check actual hardware state via CHECK_VALUE before deciding to skip. This catches cases where the BLACS flag says "armed" but hardware was changed externally (e.g., from the BigSky GUI).

How to Use

BLACS Tab Controls

  1. STOP (red) — Sends standby command. Stops lamps, closes shutter, disarms Q-switch.
  2. Warmup (blue/orange) — Starts warmup (lamps internal, shutter closed, QS off). Button turns orange when lamps are active.
  3. Arm Ext (gray/green) — Arms for external trigger (lamps external, shutter open, QS armed, QS internal). Button turns green when armed.
  4. Auto Re-Arm Ext (checkbox) — When checked, BLACS auto-arms before each shot queue and restores warmup after. Does NOT send hardware commands itself.

Typical Workflow

1. Click "Warmup" button         -- lamps fire internally, shutter closed
2. Wait for coolant temp >= 39C  -- monitor temperature in BLACS tab
3. Check "Auto Re-Arm Ext"       -- BLACS will handle arm/restore for shots
4. Queue shots in RunManager     -- BLACS auto-arms before queue, restores warmup after
   OR: Click "Arm Ext" manually  -- for single-shot manual operation

Refresh Connections (BigSky GUI)

If a second YAG is powered on after the GUI is already running, click Refresh Connections on the Home tab to re-scan COM ports without restarting.

Patterns Observed

Pattern: Fire-and-forget channels need queue_work dispatch. BLACS's program_manual path skips command-type channels (warmup, stop, start_lasing) by design. To send these from UI buttons, the tab must use @define_state(MODE_MANUAL, True) and queue_work(worker, method, ...). This is distinct from toggle/mode channels which go through the normal AO program path.
Pattern: BLACS AO widgets have a _label attribute. The built-in AnalogOutput widget includes a label that can be hidden via widget._label.hide() when the widget is placed inside a group box that already provides context.
