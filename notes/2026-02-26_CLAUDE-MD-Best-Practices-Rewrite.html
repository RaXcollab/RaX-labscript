What Changed

CLAUDE.md was rewritten from 228 to 154 lines (32% reduction) based on a survey of expert recommendations for Claude Code project instructions. The two highest-impact additions are a Verification section (Anthropic's #1 recommendation for CLAUDE.md files) and an Available Tools section listing all skills and agents. Agent orchestration rules (65 lines) were extracted into a new auto-activating skill to reduce always-loaded context. This is a continuation of the earlier session's @import and skills work.

Key Decisions

Skill vs @import for agent orchestration: Skills auto-activate based on description matching when Claude plans multi-step work. @import docs load when the directory is accessed. Agent orchestration is task-type-triggered, not file-path-triggered, so a skill is the correct mechanism. Set user-invocable: false to keep it out of the slash menu -- it's background knowledge, not a user action.
What stays in CLAUDE.md vs what gets extracted: CLAUDE.md retains universal knowledge needed in every session (repo structure, conda activation, Qt thread safety, worker paths, Do NOT Flag These). Domain-specific knowledge (@imports) and workflow knowledge (skills) are loaded on demand. The test: "Would Claude need this for a single-file bug fix?" If no, extract it.
Verification section rationale: Anthropic's official docs and multiple community guides identify verification steps as the highest-ROI addition to CLAUDE.md. Without them, Claude proposes changes without checking they work. The 7 items map to the lab's actual testing workflow (compile in RunManager, restart BLACS, check logs, etc.).

Patterns Observed

  • Content migration path: CLAUDE.md → @import docs (file-path-triggered) or skills (task-type-triggered) → agent prompts (agent-specific). Each level loads less frequently. The hierarchy is now: CLAUDE.md (always) → @imports (directory access) → skills (task matching) → agents (explicit launch).
  • Expert consensus was consistent: All 5 sources independently recommended: keep CLAUDE.md short, add verification, use project structure. Disagreement was only on formatting (some preferred YAML frontmatter, which Claude Code doesn't support).
  • user-invocable: false is underused: Most skill examples are user-facing. Background skills that auto-load based on description matching are a powerful pattern for domain knowledge that's needed intermittently but not universally.
