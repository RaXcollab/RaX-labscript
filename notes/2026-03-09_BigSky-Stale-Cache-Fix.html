BigSky GUI: Stale Cache Bug Fix

Date: 2026-03-09  •  Commit: pending  •  Context: Diagnosed and fixed silent voltage/state failures caused by optimistic caching in BigSky YAG GUI

What Changed

The BigSky GUI (BigSkyControllerAmbitious.py) cached state before serial confirmation across all remote-set and toggle methods. If a serial command timed out or failed, the GUI believed the command succeeded, creating a divergence between cached state and actual hardware. This caused voltage commands and shutter/lamp/Q-switch operations to silently fail.

All 14 affected methods were rewritten to cache state only after serial confirmation. The _remoteSet* methods were additionally changed from toggle-based delegation to direct command sends, eliminating dependence on cached state for command direction.

Bugs Found & Fixed

Bug 1: Voltage skip guard — _remoteSetVoltage() skipped the serial command if cached voltage was within ±1V of the requested value. If the cache was wrong (due to Bug 2), voltage changes were silently dropped. Fix: Removed the skip guard entirely. Deduplication belongs in the BLACS worker.
Bug 2: Optimistic cache on timeout — _remoteSetVoltage() and confirmVoltageSetting() cached the requested value even when the serial command returned None (timeout). This meant a failed command was treated as successful. Fix: On timeout, cache is left unchanged.
Bug 3: Cache-before-serial in all state methods — Toggle methods (toggleActiveStatus, toggleShutterStatus, toggleQSwitchStatus), mode-set methods (setQSwitchInternal/Burst/External, setFlashLampInternal/External), compound methods (startLaser, startWarmup), and stopLaser all updated self.*Status and GUI widgets before sending the serial command. Fix: State and GUI updates moved after if response is not None:.
Bug 4: Remote-set via toggle delegation — _remoteSetShutter/Lamps/QSwitch called the toggle methods, which inferred command direction from cached state. If cache was stale, the toggle sent the opposite command. Fix: Rewrote to send the specific command for the target state directly (e.g., >r1 for open, >r0 for close).

Key Decisions

Cache-after-confirm principle: If serial fails, state stays unchanged (stale-but-honest is better than optimistically-wrong). The serial reconnect path already queries hardware state on reconnect, so stale cache self-heals.
Deduplication in BLACS worker, not GUI: The BLACS worker's _last_sent_values dict already deduplicates redundant commands. Removing the GUI-side ±1V skip guard eliminates a second dedup layer that was masking failures.
