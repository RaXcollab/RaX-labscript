What Changed

Three new Claude Code automations for this workspace, all in the parent repo. (1) A PostToolUse hook (check-py-syntax.ps1) that runs py_compile on every edited/written .py file, so device-class typos surface at edit time instead of on BLACS restart. (2) A /repo-status skill: one-shot table of branch, ahead/behind, dirty count, and worktree-of across all 15 repos/worktrees in the workspace. (3) An /h5-inspect skill: read-only shot-file dump (tree, root attrs, and the authoritative remote_device_operation scan values) — an in-session replacement for opening HDFView.

Key Decisions

  • Phase 2 (hardening warn-git-chain.ps1 G3) skipped. The plan marks its two bypasses (PowerShell-tool git calls; git tag -m name hiding) as deliberate accepted gaps; nothing signaled the team changed its mind. Re-runnable later as its own slice.
  • PostToolUse feedback = exit 0 + JSON additionalContext. PostToolUse cannot block (tool already ran); exit 2 there is a dead-end error notice. The decision-block key is reserved for hard failures, not syntax errors.
  • Direct interpreter path for py_compile (miniconda\envs\labscript\python.exe) — no conda activation needed since py_compile needs no env vars; keeps the hook fast and synchronous.
  • Repo detection by git rev-parse --show-toplevel equality, never name patterns — keeps non-repos (rastering-stepping, envs, graphify-out) out even though they sit beside real repos.
  • Original plan rec #1 (backend tag-guard hook) was dropped at planning time — it already exists as warn-git-chain.ps1 gate G3.

Bugs Found & Fixed

$ErrorActionPreference = 'Stop' (set by _hook-common.ps1) turns native-command stderr into a terminating exception on PS 7.3+ ($PSNativeCommandUseErrorActionPreference). A failing py_compile crashed the hook instead of yielding captured text. Fix: save/restore EAP, scope 'Continue' around only the native call (check-py-syntax.ps1:21-25). Any future hook that shells out to a native command writing stderr will hit the same trap.
Em-dash in a python print header mojibaked (�) through the Git Bash console codepage during /h5-inspect testing — swapped for an ASCII hyphen. Prefer ASCII in skill-script output headers.
