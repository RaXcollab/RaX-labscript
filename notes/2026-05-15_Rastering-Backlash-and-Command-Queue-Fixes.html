What Changed

Five distinct bugs in the laser-ablation rastering GUI were diagnosed and fixed: a PriorityQueue crash on Device-Home-Both, and four backlash-related defects (no acknowledgement, double-commit, GUI freeze, stale Reading label). Methodology was /systematic-debugging (root cause by evidence/code-reading before any fix; test-first RED→GREEN; one change per cause) followed by /requesting-code-review (verdict "With fixes" — all addressed).

Two architectural decisions emerged: a monotonic tiebreaker for the motor command queue, and a "write self-reports its read-back" pattern that eliminates a priority-inversion hazard entirely rather than working around it.

Bugs Found & Fixed

Bug A — Device-Home-Both crash (7021bdf). queue.PriorityQueue received (priority, cmd) tuples. Equal-priority commands forced Python to compare un-orderable MotorCommand objects → TypeError: '<' not supported between MotorCommand. Fix: itertools.count() monotonic tiebreaker → (priority, next(seq), cmd). next() is GIL-atomic, safe for the multi-producer (ui / zmq / telemetry) → single motor-IO-thread design.
Bug B — backlash Set produced no status-log acknowledgement (9623ae7). _LOGGABLE_SUCCESS_TAGS whitelist omitted backlash_X / backlash_Y. Fix: added tags + _format_success_message backlash branch.
Bug C — single backlash edit committed twice (9623ae7). QDoubleSpinBox.editingFinished fires on both Enter and focus-out with no dedup. Fix: removed editingFinished wiring; added a dedicated per-axis "Set" QPushButton in raster_gui.ui, wired .clicked.
Bug D — GUI froze during backlash set (9623ae7). request_set_backlash was invoked with wait=True, blocking the Qt GUI thread on the motor-IO thread. Fix: fire-and-forget async; new backlash_reading_signal = pyqtSignal(str, float) fans the motor read-back from the worker thread to the GUI thread via an auto-queued connection (no wait).
Bug E — Reading label stale after Set (c06c4a0). Priority inversion: the separate read-back request_get_backlash (priority 50) and request_set_backlash (priority 100) shared one min-heap; the lower number dequeues first, so the GET could resolve against pre-SET motor state. Fix (Option C): the SET self-reports — set_backlash() returns the motor read-back (KCube does SetBacklash then GetBacklash internally), MotorResult.value carries it, _deliver_result emits backlash_reading_signal. The separate GET was eliminated entirely; no ordering hazard remains possible.

Key Decisions

Monotonic tiebreaker for object-payload priority queues: any queue.PriorityQueue / heapq carrying non-comparable object payloads must use (priority, next(itertools.count()), obj). The counter guarantees a total order so the heap never falls through to comparing the objects. Generalizable to all command-queue designs (BLACS workers, GUI motor queues).
Eliminate priority inversion, don't work around it: when a read-back must reflect a just-issued write, make the write self-report the read-back instead of enqueuing a separately-prioritized GET. Removing the second queue entry removes the ordering hazard at the source — no priority tuning, no sequencing barrier needed.
QDoubleSpinBox.editingFinished double-fires (Enter and focus-out). Any spinbox that commits to hardware must use an explicit commit button, not editingFinished. Qt-safety class lesson, applies to every hardware-committing spinbox in any GUI.
