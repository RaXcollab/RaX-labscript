Latched Digital Outputs + ZMQ Socket Reset Fix

Date: 2026-02-27  •  Commit: pending  •  Context: Per-channel opt-in latched DO for NI_DAQmx, plus pre-existing ZMQ REQ socket corruption fix

What Changed

Added a "latched digital output" feature to the NI_DAQmx driver. Latched lines are pre-set to their sequence value during transition_to_buffered (before the pseudoclock starts) and restored to their manual-mode value after the shot ends. This solves the shutter-between-shots problem: a global like LIF_SHUTTER_OPEN controls whether a shutter is open or closed for each shot, without needing timed pulse logic.

Also fixed a pre-existing ZMQ REQ socket corruption bug in the NI_DAQmx acquisition worker. After an abort, the socket could be stuck in a send/recv half-state, causing all subsequent shots to fail until BLACS was restarted.

Key Decisions

Per-channel opt-in, not all-channels. The initial proposal was to pre-latch all DO channels. User required opt-in via set_property('latched_lines', [...]) in the connection table. Rationale: only specific channels need pre-setting; blanket pre-latch could cause unintended side effects on other DO lines (e.g., trigger lines, YAG fire lines).
Three-layer merge for restore. After the shot, channel values must be restored correctly for three distinct channel types:
  1. Static/manual channels (not in DO_table): restore to initial_values
  2. Timed channels (in DO_table, not latched): restore to cached_final_values (matches what the hardware is physically outputting)
  3. Latched channels: restore to initial_values (revert to manual-mode state, overriding whatever the sequence left them at)
post_experiment restore needed. Between queued shots, BLACS calls post_experiment but NOT transition_to_manual. Without explicit restore in post_experiment, latched outputs (shutters) stay in their last-shot state until the queue ends. The fix creates a temporary DO task just for the restore write.

Bugs Found & Fixed

Shutter staying open between queued shots. Root cause: post_experiment clears tasks and returns without restoring latched values. Next shot's transition_to_buffered had no running DO task for pre-latching. Fix: _ensure_manual_DO_task() creates a temporary task in both post_experiment and transition_to_buffered.
ZMQ REQ socket corruption after abort (pre-existing). The acquisition worker's data_socket (REQ type) could get stuck in a half-sent state after an abort interrupted the send/recv cycle. All subsequent send() calls would raise zmq.error.ZMQError: Operation cannot be accomplished in current state. Fix: _reset_data_socket() closes and re-creates the socket after abort. Also added LINGER=0, context reuse, and proper shutdown cleanup.
AttributeError on init. Adding stop_tasks() at the top of start_manual_mode_tasks() (for idempotency) caused a crash on first call from init() because self.AO_task didn't exist yet. Fix: initialize self.AO_task = None and self.DO_task = None in init() before calling start_manual_mode_tasks().

How to Use

  1. In the connection table, register latched lines on the NI device: 
    ni_6535.set_property('latched_lines', ['port0/line0'], location='device_properties')
  2. In subsequences.py, the latch_digital() helper is available: 
    from labscriptlib.Main_Experiment.subsequences.subsequences import latch_digital
latch_digital(LIF_shutter, LIF_SHUTTER_OPEN)  # LIF_SHUTTER_OPEN is a RunManager global
  3. The global LIF_SHUTTER_OPEN (boolean) must exist in BaF_globals.h5. Set it in RunManager to control per-shot shutter state.
  4. The driver handles everything else: pre-latch before pseudoclock start, restore after shot, restore between queued shots.

Patterns Observed

post_experiment is not transition_to_manual. This is a recurring source of bugs. Between queued shots, BLACS only calls post_experiment (cleanup) then transition_to_buffered (next shot). transition_to_manual only runs at queue end or on abort. Any state restoration that must happen between shots needs to live in post_experiment.
ZMQ REQ sockets are fragile under abort. Any REQ socket that participates in a send/recv cycle can get stuck if the cycle is interrupted. Pattern: always implement a _reset_socket() method that closes and re-creates the socket, and call it in abort/error paths. Use LINGER=0 to prevent hangs on close.

Future Work

  • Consider adding latched analog output support (same pattern, but for AO channels controlled by RunManager globals rather than timed ramps).
  • The _reset_data_socket pattern should be audited across other acquisition workers that use ZMQ REQ sockets (e.g., NI_SCOPE worker if it has one).
  • The three-layer merge could be generalized into a base class method if other device drivers need similar post-shot restore logic.
