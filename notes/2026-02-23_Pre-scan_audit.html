Investigated & Cleared

These areas were thoroughly audited and found to be clean:

  • Qt thread safety — all 7 devices use inmain() correctly, no qtlock for widget calls, PUB-SUB threads use pyqtSignal bridges
  • Worker paths — all use user_devices.X.blacs_workers.Y
  • ZMQ protocol compliance — HELLO, PROGRAM_VALUE, CHECK_VALUE with timeout/error handling
  • Delta tracking & poll race protection — correctly implemented in BigSkyHub
  • All register_classes.py files — correct references
  • CLAUDE.md, BLACS_COMMUNICATION_CONTRACT.md, all 6 agent prompts — consistent and current
  • Analysis pipeline — analysis.py, filtering.py, NI_SCOPE.py, Abs_data.py all robust
  • Backend repos — blacs/, labscript-devices/, labscript-utils/ clean, no local mods
  • Labconfig — all sections present, ports consistent
  • Rastering GUI thread safety — proper _state_lock usage throughout
  • RunManager globals — BaF_globals.h5 with 5 groups, well-organized for parameter scans
  • BLACS faulthandler.log — empty (no segfaults)

Not Issues (Investigated, Dismissed)

  • BigSkyHub num_lasers — intentionally variable (1 or 2) per experiment. BLACS restore_save_data() handles stale channels gracefully via FrontPanelSettings.check_row(). Recurring YAG_2 log messages are debug-level poll noise.
  • Sequence "undefined globals" — tYAG, tstart, tend, etc. are RunManager globals injected from BaF_globals.h5 at compile time. Standard labscript pattern.
  • Legacy sequences — RunManager only compiles the selected file. Old-hardware sequences are useful reference, not clutter.
  • PrawnBlaster COM port error — one-time stale port designation, already fixed.
  • __pycache__ files — auto-managed by Python.
  • Jupyter checkpoints — auto-managed by Jupyter.
