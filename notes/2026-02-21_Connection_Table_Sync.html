What Changed

The Closed_cell.py sequence was missing two device blocks (RasteringDevice and BigSkyHub) that exist in the active connection_table.py. Both blocks were copied verbatim to bring the sequence header into full sync. CLAUDE.md was updated with machine identity context and the connection table duplication convention.

Key Decisions

Verbatim copy, not refactor. The RasteringDevice and BigSkyHub blocks were copied exactly from connection_table.py rather than attempting to DRY up the duplication. This is intentional: labscript sequences must carry their own complete connection table header because they are compiled independently. The duplication is a labscript architectural constraint, not a code smell.

Patterns Observed

Connection table drift is a recurring risk. Every time a device is added to connection_table.py, ALL active sequence files must be updated to match. There is no automated check for this. The backup files (connection_table_closed_cell.py, connection_table_fromLyman.py, connection_table_photon_counting.py) are all significantly stale and should not be relied on.

The connection_table_closed_cell.py backup still references COM7 (should be COM4), lacks all ZMQ devices, and has dummy_line uncommented. It is a pre-ZMQ-integration snapshot.
