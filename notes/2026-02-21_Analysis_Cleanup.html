Lyse Analysis Code Cleanup

Date: 2026-02-21  •  Commit: 41659a8  •  Context: Cleaning up Main_Experiment analysis scripts and adding a dedicated analysis agent

What We Changed

The lyse analysis code in userlib/analysislib/Main_Experiment/ had accumulated dead code (~100 lines of commented-out blocks), duplicated drift-correction logic, hardcoded timing values (flagged with "HARDCODED!!" comments), wildcard imports, and a hardcoded NI_SCOPE sample rate. The utility files (filtering.py, NI_SCOPE.py, Abs_data.py) were already well-structured and needed no changes beyond improving process_trace().

Key Improvements

1. Adaptive Drift Correction (filtering.py)

The old process_trace() required hardcoded absolute time values for the fitting regions. The new version auto-detects them:

RegionOld (hardcoded)New (adaptive)
Before YAG beforeYAG_time=1.95 ms (absolute) time_ms < tYAG_ms - margin_ms (relative to YAG trigger)
After signal after_abs_time=10.0, end_time=15.0 ms (absolute, and analysis.py had a bug: end < start) time_ms > time_ms[-1] - tail_ms (last 1ms of trace)

Additionally, a slope check on the late-time residuals warns if the signal has not fully decayed:

[process_trace] Warning: late-time slope = 0.0234 V/ms (threshold 0.01).
  Signal may not have fully decayed.
Bug found & fixed: The old analysis.py had after_abs_index=30ms and end_index=5ms. Since 5 < 30, the post-absorption fitting region was empty. Drift correction was only using the pre-YAG baseline, which is insufficient for long traces. The adaptive approach eliminates this class of bug entirely.

2. NI_SCOPE Sample Rate from HDF5

The old code hardcoded 1_000_000 Hz with a comment: "HARD CODED!!! REPLACE WITH SAVE/IMPORT!!". The new code reads min_sample_rate from the HDF5 connection table properties:

with h5py.File(h5_path, 'r') as f:
    props = labscript_utils.properties.get(f, 'NI_SCOPE', 'connection_table_properties')
    sample_rate = float(props['min_sample_rate'])

4. Error Handling

Trace extraction now uses try/except. If a trace is missing, the script prints a warning and shows a placeholder instead of crashing the lyse pipeline.

5. Multishot Template

analysis_multishot.py was mostly dead code (commented-out image averaging, pixel_sum reading via manual directory walk). Replaced with a clean template showing the proper lyse.data() aggregation pattern.

New Agent: lyse-analysis

A new dedicated agent at .claude/agents/lyse-analysis.md specializes in two distinct analysis contexts:

ContextPriorityScope
Real-time lyse scripts Performance-critical Single/multi-shot scripts in analysislib/ that run during experiments. Minimize HDF5 I/O, use vectorized numpy, fail gracefully.
Offline analysis notebooks Thoroughness Jupyter notebooks for post-experiment analysis. Batch loading via Abs_data.load_sequence(), NI_SCOPE.load_ni_scope_sequences(). Publication-quality plots.

The agent knows the full utility library API (filtering.py, NI_SCOPE.py, Abs_data.py), HDF5 data structure, and lyse conventions.
