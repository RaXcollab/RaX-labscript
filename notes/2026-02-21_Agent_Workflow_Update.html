What Changed

Key Decisions

Why split labscript-amo-expert into 3 agents?

The original agent covered 10+ topics across 152 lines: Qt thread safety, device scaffolding, RemoteControl patterns, experiment sequences, NI hardware, connection tables, debugging methodology, worker paths, state machine ordering, and analysis. During the BigSkyHub integration — a device-building task it was purpose-built for — it was never invoked. The root cause was twofold: (1) plan mode's agent selection couldn't match its broad description to a specific task, and (2) its breadth diluted its signal for any single task type.

The split follows task boundaries:

AgentDomainLinesInvoke When
device-builder BLACS device scaffolding, RemoteControl pattern, worker/tab overrides ~91 Creating or modifying device classes
blacs-expert Qt thread safety, state machine, PUB-SUB threading, pitfalls ~66 BLACS crashes, segfaults, event ordering issues
amo-expert Experiment sequences, connection tables, NI hardware, runmanager, shot lifecycle ~67 Writing sequences or configuring hardware

Why add orchestration rules to CLAUDE.md?

Agent descriptions alone are not sufficient to trigger invocation. The assistant needs a dispatch table mapping task types to agents, plus explicit rules like "session-notes is mandatory." Without this, the user becomes the orchestrator — exactly what agents should prevent.

Why make session-notes mandatory?

Session notes were "proactive" (advisory). In practice, the assistant skipped them unless reminded. Making them mandatory ensures decisions are captured even when the assistant is focused on implementation.

Patterns Observed

Density vs. Discoverability tradeoff

CLAUDE.md serves two audiences: (1) the assistant, which reads it on every session start, and (2) specialized agents, which need deep domain knowledge. The fix is to keep CLAUDE.md as a dispatch layer (what + where) and push deep knowledge into agent prompts (how + why). This session trimmed ~40 lines from CLAUDE.md and added ~25 for the orchestration section, achieving a net reduction while adding new capability.

Deferral pattern emerging

All 6 agents now have "Defers To" sections establishing a directed graph: diagnostics → blacs-expert → device-builder, amo-expert → device-builder, lyse-analysis → amo-expert. This prevents agents from attempting work outside their domain.

Future Work

  • Validate agent invocation in practice: The next device integration session should test whether the orchestration rules actually trigger agent invocations without user prompting.
  • Plan mode agent selection: The "plan mode integration" note tells the assistant to use specialized agents as Explore/Plan substitutes. This is a workaround; the underlying issue is that plan mode's agent picker may not match task-specific agents. Monitor whether this workaround is sufficient.
  • Agent prompt size budget: Each agent is currently 60-90 lines. If they grow, consider whether the split needs further decomposition or whether some content can move to reference docs.
