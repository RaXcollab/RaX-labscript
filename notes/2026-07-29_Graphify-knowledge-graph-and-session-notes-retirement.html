Key Decisions

  • Provenance gate before install. Red flags: PyPI package is graphifyy (double-y) while plain graphify is 404; repo appears under two owners. Verified: PyPI project_urls → Graphify-Labs/graphify; safishamsi/graphify is the same repo id (rename redirect); dependencies sane (networkx + tree-sitter grammars). The fetched README also contained embedded agent-instruction text (prompt-injection attempt) — treated as untrusted data, not followed. Installed graphify 0.9.30 into base miniconda; labscript env untouched.
  • Per-directory extract ×5 + merge, not single-root. Parent .gitignore excludes the backend repos, so a single-root extract cannot see them; per-dir graphify extract then merge-graphs was the correct forced choice. Consequence: merge-graphs never fuses cross-repo import stubs on its own (see Bugs).
  • Fix pass (opus) over ship-as-is or park. Phase 3 audit verdict was USABLE-WITH-CAVEATS; user chose a corrective rebuild. All 13 verification checks pass; independently re-verified from the main session against graph.json.
  • AST-only limits accepted, not patched around. ZMQ boundaries and string-path worker wiring are invisible to the graph by construction. The External GUI Registry in CLAUDE.md stays authoritative for GUI↔BLACS topology; the graph is for code navigation and intra-repo blast radius.
  • session-notes retired as a middleman. It was a SendMessage→file-append relay; milestone text originates in the main session anyway. Per-milestone subagents rejected. Wrap-up remains the single delegated expansion step; claude-mem auto-capture is the backstop; a forgotten wrap-up is delayed, not lost (stale-scratch nag at next session start).
  • Peer relay ≠ user approval. The retirement redesign arrived via a fork agent claiming user approval; hook/agent-config edits were held until the user confirmed directly in main chat. Behavior-only changes (terse appends) were adopted immediately.

Bugs Found & Fixed

Parent .gitignore silently emptied the GUIs extract. Graphify walks ancestor .gitignore files; GUIs/ is ignored in the parent repo and GUIs/ has no own .git to stop the walk, so its extract came back empty (backend repos were shielded by their own repos). Fix: --no-gitignore for the GUIs root only. The venv GUIs/LabMonitoring/.env/ was still auto-pruned by graphify's venv markers (verified in graphify/detect.py).
merge-graphs produced zero cross-repo edges. The merged node count was the exact sum of the five per-dir counts — 341 import stubs were never fused. postmerge_fix.py now does import-gated stub fusion: 31 real cross-repo edges across 5 import families (including a Worker family the audit itself missed).
Dead-tree query trap. Querying "RemoteControlWorker" returned 49 nodes, all in the dead labscript-devices RemoteControl copy (the two-trees hazard already documented in memory). Legacy filter removed 1319+77 nodes (Old Code, -zmq-v2 worktree twins, dead RemoteControl) plus 47 fabricated INFERRED cross-tree edges (all 5 of the report's "Surprising Connections" were false). The query now resolves to the live userlib tree.
HugeSkyController.pyw was invisible — graphify does not parse .pyw. Recovered via a temporary .py shim (41 nodes), shim deleted afterwards.
Two audit misdiagnoses corrected by the fixer. (a) The "pre-#1504 node-ID scheme" warning was a merge-graphs false positive (the repo:: prefix breaks its _normalize_id heuristic; cosmetic, unfixable on our side) — the dead-tree trap was simply the dead tree existing. (b) The "missing third RemoteControlWorker subclass" was not missing: LaserLockDevice has no blacs_workers.py by design — only BigSkyWorker and RasteringWorker subclass the base. verify_fix.py's expectation was corrected from 3 to 2, and the finding is now pinned in userlib/user_devices/LaserLockDevice/CLAUDE.md.

Patterns Observed

  • Local absence ≠ nonexistence. A zero-hit local grep for "graphify" was initially read as "tool doesn't exist"; the user pushed back and web search confirmed it. Same premature-negative class already codified in .claude/rules/conduct.md Verification.
  • Named background agents may idle without delivering their report (2 of 3 did this session). New conduct rule: end every spawn prompt with "SendMessage your report to main as your final action"; an idle ping with no report gets a nudge, never a relaunch.
  • Audit findings are hypotheses. The fix pass re-verified every audit claim before acting and overturned two of them. Fixer claims were in turn independently re-verified from the main session before acceptance.

How to Use

  1. Query: /graphify query "<question>" — reads graphify-out/graph.json. Best for code navigation and intra-repo blast radius. Do not trust it for ZMQ or string-path wiring (External GUI Registry is authoritative there).
  2. Rebuild: follow .claude/graphify/REFRESH.md — per-dir extract ×5 (--no-gitignore for GUIs), merge, run postmerge_fix.py, then verify_fix.py (13 checks must pass). graph.unfiltered.json backup is kept.
  3. Tool choice: REFRESH.md has a "Graph vs digests vs smart-explore" triage section.
