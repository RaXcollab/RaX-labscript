Fix: BLACS Relaunch Crash After Connection Table Recompile

Date: 2026-02-21  •  Repo: labscript-utils  •  Commit: c2c767c

Problem

After recompiling the connection table and clicking "Restart", BLACS sometimes failed to relaunch with this error: 

pywintypes.error: (87, 'SetConsoleMode', 'The parameter is incorrect.')

The crash was intermittent — it depended on timing between the parent process exiting and the child process starting up.

Root Cause

BLACS relaunches itself via subprocess.Popen([sys.executable] + sys.argv) in blacs/__main__.py:124 with no console creation flags. The child process inherits the parent's console handle. When the parent exits, that handle becomes stale.

At import time, labscript_utils/__init__.py calls zprocess.disable_quick_edit(), which:

  1. Calls GetConsoleMode() — succeeds (wrapped in try/except in zprocess)
  2. Computes a new mode with quick-edit disabled
  3. Calls SetConsoleMode(new_mode) — FAILS (no try/except in zprocess)

The gap is in the zprocess library: it protects GetConsoleMode() but not SetConsoleMode().

Fix

Wrapped the zprocess.disable_quick_edit() call in labscript_utils/__init__.py with a try/except: 

try:
    zprocess.disable_quick_edit()
except Exception:
    # Console handle may be stale after BLACS relaunch via subprocess.Popen().
    # Not critical for GUI apps - safe to ignore.
    pass

Why This Approach

Workaround over root cause fix: An alternative was to change the Popen call to use CREATE_NEW_CONSOLE or CREATE_NO_WINDOW flags. However, changing process creation flags could affect logging and console output visibility. Since disable_quick_edit is non-essential for a Qt GUI app, the try/except is the safer and simpler fix.

labscript-utils/labscript_utils/__init__.py Wrapped disable_quick_edit() in try/except (lines 97–105)

Verification

Tested by recompiling the connection table and restarting BLACS from PowerShell. BLACS now relaunches successfully.
