Agent Orchestration Upgrade: Domain-Aware Routing

Date: 2026-02-23  •  Commits: 5631bad, 9d1821e  •  Context: Introspection from the pre-scan codebase audit (see 2026-02-23_Pre-scan_audit.html) revealed systemic false positives from generic agents. This upgrade adds domain-aware routing to prevent them.

What Changed

The pre-scan audit produced 7 user corrections, 5 of which shared one root cause: generic Explore agents applying software engineering heuristics to experimental physics code (flagging RunManager globals as "undefined", treating num_lasers=1 as a bug, recommending __pycache__ cleanup, etc.). This upgrade adds a file-to-agent routing table to CLAUDE.md, an explicit anti-pattern list, and splits the deliverables workflow into a dedicated wrap-up agent with a mandatory checklist.

Core principle: When a broad search or audit touches domain-specific files, findings must be validated by the corresponding domain agent before being reported to the user. Generic agents lack physics-lab context.

Key Decisions

1. Route user_devices/ to device-builder (single entry point)

Rather than routing to "blacs-expert or device-builder", we route to device-builder which is instructed to confer with blacs-expert and amo-expert. One entry point per path, collaboration happens inside.

2. Single log errors are yellow, not red

The diagnostics agent now triages single-occurrence errors as yellow observations ("note for potential pattern") rather than critical issues. They're still logged so users can investigate patterns later.

3. Plan agent use upfront, not reactively

Previously: "at session end, launch wrap-up." Now: during the planning phase, the orchestrator walks through the full agent pipeline (domain agents + session-notes + wrap-up) and includes them all in the plan itself. Deliverables are never an afterthought.

4. session-notes / wrap-up split

session-notes is lightweight background note-taking (scratch file, pattern spotting). wrap-up owns the heavy deliverables pipeline (diffs → commits → lab note → introspection → context updates). Different tasks, different agents.

Anti-Pattern List ("Do NOT Flag These")

  • RunManager globals (tYAG, tstart, etc.) appearing "undefined" in sequences
  • __pycache__/ and .ipynb_checkpoints/ directories
  • Single-occurrence log errors without recurrence
  • Connection table parameters differing from hardware maximums
  • Inline function definitions in old Jupyter notebooks

Patterns Observed

Root cause pattern: 5/7 audit corrections = generic SW engineering heuristics applied to experimental physics code. Domain agents have the right context; generic agents do not. The routing table is the structural fix.
Deliverables friction: User had to remind about introspection and lab notes multiple times across sessions. The wrap-up agent with its mandatory checklist is the structural fix.
