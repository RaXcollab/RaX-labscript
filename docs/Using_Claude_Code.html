Using Claude Code with Labscript

Last updated: 2026-03-03  •  Version: 6.1  •  Canonical reference for the RaX lab Claude Code setup

What is Claude Code?

Claude Code is an AI coding assistant that runs in a terminal (or VS Code extension). It can read files, edit code, run commands, and search the codebase. We have it configured with project-specific knowledge about our labscript-suite setup so it can help with debugging, writing new device classes, and understanding the codebase.

How to Launch

Open a terminal in the labscript-suite folder and run claude. Or use the Claude Code VS Code extension (Ctrl+L to open the chat panel).

What Claude Code Already Knows

Every session, Claude automatically reads CLAUDE.md in the repo root. This gives it:

  • Multi-repo structure (labscript-suite = user-facing, blacs/ / labscript-devices/ / labscript-utils/ = separate backend repos)
  • Where custom devices live (userlib/user_devices/)
  • Key coding conventions (e.g., use inmain() not qtlock for Qt widget calls in BLACS tabs)
  • Log file locations (logs/BLACS.log, logs/BLACS_faulthandler.log)
  • How to activate the conda environment
  • The ExternalSoftware/RemoteControl communication pattern (REQ-REP + PUB-SUB)
  • Design philosophy: modularity over simplicity, need-driven complexity, our fork is ground truth
  • NI_DAQmx output worker lifecycle: queued-shot flow, latched DO pattern, three-layer merge restore
  • Labscript DSL & device driver API reference (class signatures, sequence methods, constraints)

Detailed reference docs (docs/*.md) load conditionally via path-scoped rules in .claude/rules/ref-*.md — BLACS device patterns load when editing user_devices/ or blacs/, labscript API loads for sequences and devices, analysis API loads for analysislib/. Domain rules in .claude/rules/ auto-activate for matching file paths (Qt safety for devices, timing safety for sequences, etc.).

Agent Memory

Five agents have persistent memory that accumulates knowledge across sessions:

  • blacs-expert — device quirks, crash patterns, thread safety fixes
  • device-builder — which patterns worked for which devices, integration lessons
  • labscript-diagnostics — recurring error patterns and resolutions
  • amo-expert — timing patterns, active globals, sequence conventions
  • context-auditor — best practices catalog, audit history, corroborated findings from research

Memory files are stored in .claude/agent-memory/{agent-name}/. When the same issue appears again, the agent can reference its memory for the resolution that worked last time.

Skills Preloading

All 8 agents have skills: frontmatter that injects shared context at launch. Every agent gets the agent-workflow skill (routing table, orchestration rules, deliverables checklist). device-builder also gets check-guis for ZMQ port validation when scaffolding external GUI integrations.

Skills (Slash Commands)

Skills are reusable workflows invoked with /skill-name. They run in the main conversation.

Context Management

Context is the most important resource to manage. Claude's performance degrades as the context window fills with irrelevant information from earlier tasks.
  • /clear — Reset context between unrelated tasks. If you debug BLACS, then tweak a sequence, then fix analysis — use /clear between each.
  • /rename — Give sessions descriptive names (e.g., /rename bigsky-disconnect-fix) so you can find them with claude --resume.
  • Status line — Shows context usage %, current model, and session name at the bottom of the terminal. When context gets high (>70%), consider /clear or /compact.
  • Auto-compaction — When context fills, Claude automatically summarizes. The CLAUDE.md includes preservation rules ensuring the routing table, conda command, and suppression list survive compaction.
  • Subagent delegation — Heavy research is delegated to agents that work in separate context windows, keeping your main conversation clean.

Orchestration

Three-phase workflow: (1) session-notes launches automatically in background. (2) Domain agents do the work. (3) wrap-up runs at the end for deliverables. All three are planned upfront, not as afterthoughts.
Cross-audit for safety-critical changes: Changes to BLACS workers (which control live hardware) require every claim to be audited by blacs-expert AND cross-audited by amo-expert. Plans must include an Agent Dispatch Table (which agents, which phase) and an Agent Audit Trail (which claims audited, by whom).

Safety & Permissions

  • Push guard hook: git push to backend repos (blacs/, labscript-devices/, labscript-utils/) is blocked by a PreToolUse hook. Claude will ask for explicit confirmation.
  • Notification hook: When Claude is waiting for input or done with a task, a Windows notification appears.
  • Pre-approved operations: Common git commands, conda activation, and pip commands run without permission prompts.

Tips

  • Use /clear between unrelated tasks. Single most impactful thing for session quality.
  • Name sessions with /rename. Resume later with claude --resume bigsky-debug.
  • Use /check-guis before BLACS. Catches "why is my tab red?" before it happens.
  • Use /check-sequence before compiling. Catches missing globals and device name mismatches.
  • Be specific. "Fix the bug" is worse than "RemoteControlTab crashes when I click reconnect."
  • Watch the status line. When context >70%, use /clear or /compact.
  • Plan mode for big tasks. Claude proposes a plan before making changes. You approve first.
  • It knows about separate repos. Say "commit to labscript-devices" and "don't push."
