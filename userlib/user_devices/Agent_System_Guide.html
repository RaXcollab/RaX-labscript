Agent System Guide

Date: 2026-02-21  •  Version: 1.0  •  Context: Canonical reference for the 6-agent system in the RaX Labscript suite workspace

Overview

The workspace uses 6 specialized agents stored in .claude/agents/. Each agent has a focused domain and defers to other agents for out-of-scope questions. The main assistant uses the Agent Orchestration table in CLAUDE.md to select which agents to invoke for a given task.

Orchestration Rules

The main assistant selects agents based on the task type. These rules are codified in the Agent Orchestration section of CLAUDE.md.
Task TypeAgentsWhen
Any non-trivial workflow session-notes (background) At session start, always
New device integration + device-builder During planning and implementation
BLACS crash / thread issue + blacs-expert then labscript-diagnostics Immediately
Experiment sequence design + amo-expert When writing sequences or connection tables
Analysis work + lyse-analysis When touching analysislib/

Plan Mode

When operating in plan mode, the assistant should use specialized agents (device-builder, blacs-expert, amo-expert) as its Explore/Plan agents for domain-matching tasks, rather than defaulting to generic exploration.

The Deferral Pattern

Each agent has a "Defers To" section listing other agents it hands off to for out-of-scope questions. This prevents agents from attempting work outside their domain and creates a directed graph of expertise. 

amo-expert ──────┬──► device-builder ──► blacs-expert
                 │                           ▲
lyse-analysis ───┤                           │
                 │                           │
diagnostics ─────┴───────────────────────────┘

session-notes ◄── all agents (documentation)

Examples:

  • amo-expert defers to device-builder for creating new device classes
  • device-builder defers to blacs-expert for Qt thread safety questions
  • labscript-diagnostics defers to blacs-expert for architecture questions
  • lyse-analysis defers to amo-expert for experiment design context
  • All agents note that session-notes should already be running

Session Notes Workflow

session-notes is mandatory for all non-trivial workflows. The assistant launches it in the background at session start.

Two Modes

  1. Active note-taking — Resumed at milestones to log decisions, bugs, patterns, and structural changes into .claude/session-scratch.md (transient, not committed). If file writes are unavailable (e.g., plan mode), notes accumulate in agent memory instead.
  2. Wrap-up — Compiles scratch notes + git diffs into 4 deliverables:
    • Commit message — Follows repo conventions (imperative title, file-level bullets with what + why)
    • HTML lab note — Structured document for OneNote with decisions, bugs, patterns, file change tables
    • Context updates — Proposed edits to CLAUDE.md or agent prompts (when warranted)
    • Session introspection — What went well, friction points, recommended actions
