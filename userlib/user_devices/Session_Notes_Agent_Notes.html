Session Notes Meta Agent

Date: 2026-02-21  •  Commit: d5b6541  •  Context: Adding a documentation agent that actively scribes during sessions and produces structured deliverables

What Changed

We created a new session-notes agent that operates in two modes: active note-taking during a work session (logging decisions, bugs, patterns into a scratch file) and wrap-up at the end (compiling scratch notes + git diffs into commit messages, HTML lab notes, and CLAUDE.md updates). This addresses the recurring manual overhead of producing three separate documentation artifacts that all derive from the same "what changed and why" analysis.

Key Decisions

1. Active Scribe vs. Post-Hoc Summarizer

The original design was a post-hoc agent that runs at the end of a session and reconstructs what happened from git diffs. We upgraded to a two-mode design where the agent actively takes notes during the session. The rationale: the richest documentation comes from capturing decisions as they happen, not reconstructing them from diffs after the fact. Git diffs show what changed but not why.

2. Scratch File as Memory

The agent maintains .claude/session-scratch.md as a transient running log. Each entry is timestamped and categorized (DECISION, BUG, PATTERN, CHANGE, TODO, CONTEXT). This file bridges the gap between ephemeral conversation context and persistent deliverables. It is deleted after wrap-up and never committed.

3. Pattern Recognition

One of the most valuable features: as scratch entries accumulate, the agent looks for recurring themes (e.g., "third Qt thread safety issue this month", "this import pattern keeps appearing"). These become a "Patterns Observed" section in the lab note. Humans tend to miss patterns across long sessions.

Resume-based workflow: The agent is launched once via Task and then resumed at milestones using Task(resume=agentId). This preserves its full context across the session without re-explaining everything each time.

How to Use

  1. Start of session: Say "start taking notes" — the agent creates the scratch file
  2. During session: The main assistant resumes the agent at milestones with tagged observations
  3. End of session: Say "wrap up this session" — the agent compiles everything into:
    • Commit message (per repo, following existing conventions)
    • HTML lab note (stored contextually near the changed code)
    • CLAUDE.md / agent prompt updates (only when structural changes warrant it)
  4. Review drafts, confirm, and the agent writes the files
