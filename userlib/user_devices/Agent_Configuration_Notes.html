Agent Configuration & Cross-Repo Awareness

Date: 2026-02-21  •  Context: Retrospective on rastering GUI BLACS integration — improving agentic workflow for future integrations

What We Changed

After integrating the rastering GUI into BLACS, we identified friction points in the agent-assisted workflow: too many planning rounds, no cross-repo awareness between agents, no checklists for common tasks. These changes address all of those.

Key idea: The BLACS_COMMUNICATION_CONTRACT.md acts as a signpost — external GUI agents read it to learn the protocol without needing to explore the labscript-suite codebase. The labscript-amo-expert knows to check external GUI folders for local agents and delegate domain questions to them.

BLACS Communication Contract (Summary)

The full document lives at userlib/user_devices/BLACS_COMMUNICATION_CONTRACT.md. Key points:

ProtocolFormatPurpose
ZMQ REQ-REP {"action": "HELLO|PROGRAM_VALUE|CHECK_VALUE", "connection": str, "value": any} Synchronous control: set values, read values, connection check
ZMQ PUB-SUB "{topic} {value}" (space-separated string) Async monitoring: heartbeat (~1 Hz), positions (~4 Hz), status (~1 Hz)

Integration Workflow Checklist

  1. Decide: subclass RemoteControl or use it directly?
  2. Check for local agents: look in the external GUI folder for .claude/agents/ — use local agents for domain questions, labscript-amo-expert for BLACS-side architecture
  3. External GUI side: add ZMQ server (HELLO, PROGRAM_VALUE, CHECK_VALUE + optional PUB-SUB). Follow BLACS_COMMUNICATION_CONTRACT.md
  4. Create device class (if subclassing): 5 files in userlib/user_devices/{DeviceName}/
  5. Connection table entry: import, instantiate, add children
  6. Test: start GUI first, then BLACS. Verify REQ-REP + PUB-SUB + buffered mode
  7. Update registry: add to External GUI Registry in CLAUDE.md
